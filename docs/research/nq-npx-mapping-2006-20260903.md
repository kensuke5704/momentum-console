# 2006 N-Q → N-PX Security Mapping Validation

Date: 2026-09-03 JST
Branch: `research/cagr40-new-alpha-20260901`

## Purpose

Measure whether legacy N-Q PIT holdings descriptions can be mapped to stable historical ticker/security identities using a free N-PX-derived security master, without using return or strategy-performance information.

## Mapping rule

- Normalize issuer text conservatively: uppercase, `& -> AND`, common legal suffix normalization, punctuation collapse.
- Remove only trailing N-Q footnote markers such as `(a)` before matching.
- Automatically accept only a unique exact normalized issuer match to an N-PX `(ticker, securityId)` identity.
- Ambiguous exact matches remain ambiguous.
- Fuzzy matches are diagnostics only and are never accepted automatically.
- Obvious parser artifacts such as `Fund (cost ...)` are excluded from the eligible mapping denominator and reported separately.

## Interpretation

The matching method itself is structurally viable: several known ETF series reach high weight coverage with exact-only matching and zero ambiguity. The large cross-series dispersion indicates that the main current limitation is N-PX security-master coverage rather than a need for aggressive fuzzy matching.

Therefore the mapping rule is frozen for the next diagnostic. The N-PX master sample is expanded from 24 to 96 deterministic equal-quantile filings with the same non-performance-based selection rule. The comparison is intended to isolate the marginal benefit from security-master coverage alone.

Do not run 2006–2018 strategy performance at this stage.
